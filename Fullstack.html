FIG. 11 — WHY THIS ORDER

The pedagogy, defended.

Every sequencing decision here is deliberate. Here's the reasoning.

React is JavaScript wearing a costume. Every "React problem" — stale closures, effect timing, immutable updates — is really a JavaScript problem. Learn the language first and React becomes a thin layer you understand instead of a magic box you memorize.

Relational thinking — keys, joins, normalization — is the vocabulary of data itself. NoSQL doesn't remove the need for modeling; it just moves the decisions into your application code, where they're easier to get wrong. Learn the rules before you bend them.

REST teaches the fundamentals of API design — resources, methods, status codes, idempotency — on plain HTTP, with no tooling in the way. GraphQL solves problems you only feel once you've built a few REST APIs and hit those problems yourself.

You can't meaningfully test what you can't yet build. Testing is introduced the moment you have real code worth protecting — APIs, components, flows. From phase 13 onward, every project expectation includes tests. The habit starts there and never stops.

Employers hire people who are dangerous with one stack, not tourists in five. The concepts — components, APIs, queries, auth, deployment — transfer completely once you're deep. Learning your second stack takes weeks, not months, because the mental models are already built.

Knowledge that never becomes code evaporates within days. Projects force the uncomfortable part — blank files, real errors, decisions with no tutorial — which is exactly the part that builds skill. They also compound into the portfolio you'll interview with.

Deployment makes everything real: environments, secrets, downtime, logs. System design is mostly reasoning about what happens when those things fail at scale — and that reasoning lands far harder once you've personally watched a deploy break at 1am.

No. That's the entire premise. Every phase you skip becomes a hole that leaks into every phase after it — and interviews have a way of finding the holes. Move fast through what's easy, but clear every checkpoint, build every project, pass every quiz.
